# Build rules — shell, scrolling, fill and responsiveness

Referenced by `skills/gushwork-dashboard/SKILL.md`. Every rule here came from a defect found
while building a real dashboard, not from preference.

The working reference implementation is `preview/meta-ads-app.html`, generated by
`preview/_build_meta_ads_app.py` with `preview/_meta_ads_app.css`.

### Scrolling — exactly one region scrolls

`dashboard-build` is a **fixed shell whose Slot scrolls.** Nothing else does.

- `html, body { overflow: hidden }` and the shell locked to the viewport. If the document
  scrolls, the rail scrolls away with it — which is wrong and looks broken.
- **`.slot > * { flex: 0 0 auto }`** is mandatory. Sections are flex items in a
  fixed-height column, so they default to `flex-shrink: 1` and get **compressed** instead
  of letting the slot scroll. This silently collapsed a 228px chart body to 56px — the
  chart rendered as an empty box with a stray axis label.
- The **rail is `overflow: hidden`**; only its nav list scrolls. The user-card sits outside
  that scroller so it stays pinned to the bottom. Nine nav items plus the user-card need
  ~683px, so below roughly 700px tall the nav must scroll — the user-card must not.
- `section/header` never scrolls. It is `flex: none` above the slot.

### Horizontal — measured widths are exact

**Never clamp a horizontal measured value.** The 260 rail, the 1084 section, the
`card-layout` splits and the table's data-column widths are what they are. On wide screens
change the **column count**, not the sizes.

- Cards **fill** their section — the intrinsic 286 and 160 are floors, not fixed widths.
- **`card-layout` splits:** `KPI cards=1` is 400/676 (36.9% / 62.5%), `=2` is 580/496
  (53.5% / 45.8%), `=3` is a full-width KPI row above a full-width analytics row.
- **Tables: leave the first column unsized.** If every column has an explicit width the
  browser spreads leftover space across all of them — a 16px action column measured 84px
  on a 1600 display while data columns drifted past their measured widths. Unsized first
  column absorbs the slack; pin the action column.

### Vertical — measured values are the ceiling

Vertical rhythm clamps, with **the Figma value as the maximum**, so a tall viewport renders
the component exactly as drawn and a short one compresses rather than pushing content below
the fold.

| Variable | Range | Measured |
|---|---|---|
| slot padding + section gap | 16 → 40 | 40 |
| kpi-card height | 140 → 198 | 198 |
| kpi header→value spacer | 12 → 80 | 80 |
| chart plot height | 120 → 200 | — |
| header top padding | 16 → 40 | 40 |
| rail padding | 12 → 24 | 24 |
| rail title→nav gap | 14 → 40 | 40 |
| nav group gap | 8 → 24 | 24 |

### Charts — align by grid, never by matching gaps

**A bar chart must put each label in the same grid row as its bar.** Two independent
columns — a stack of 12px labels beside a stack of 10px bars sharing one gap — accumulate
2px of drift per row. Measured at 14px on the first row. Reserve ~52px at the track's right
edge for the value label so the longest bar cannot overflow.

A continuous axis (`Type=Line`) is different: `justify-content: space-between` over a fixed
height is correct there.

### Wide screens

| Breakpoint | Change |
|---|---|
| ≥ 1800 | analytics grid 3 → 6 columns at `KPI cards=1`; 2×3 → 3 at `=2`. Cap the KPI area (480 at `=1`, 820 at `=2`) — left to the 36.9% split a single kpi-card reaches 715px, a near-empty box around a 32px number. |
| ≥ 2200 | `=2` grid → 6 columns; slot padding-inline → `clamp(40px, 4vw, 96px)` |

### Multi-page apps — the rail is chrome, not page content

`dashboard-build` describes **one** page and the library has no pattern for moving between
pages inside one shell. Real products have several. Declared as a created element in
`notices/2026-08-06-meta-ads.md`; until it is in Figma, build it this way.

- **The rail persists; the header and slot swap.** Nav rows are `list-item` and the active
  row uses its measured `selected` state (`--gw-color-neutral-50`). No new visual element —
  what is new is that the rail became persistent chrome rather than page content.
- **One page is one Section stack.** Do not let pages share a slot or stack scroll positions.
- **Every page keeps its own `section/header`.** The title changes with the page; the rail
  does not.
- **`list-item` group headers stay put across pages.** They label the nav, not the page.

### Choices that are not measured — say so in the code

Figma has no spec for these. Each is a product decision and must be commented as such so a
later reader never mistakes it for a measured value:

- **The fluid shell.** `dashboard-build` is a fixed 1440 × 888. A responsive build keeps
  the rail at 260 and flexes the container.
- **Hidden scrollbars.** `scrollbar-width: none` plus a zero-size `::-webkit-scrollbar`.
  Costs a scroll affordance — there is no cue that content continues below the fold.
- **Any vertical clamp minimum.** The maximum is measured; the floor is judgement.
