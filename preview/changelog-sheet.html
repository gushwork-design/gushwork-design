the changelog sheet is a reading page, not a table

Redesigned after Utsav pointed at code.claude.com/docs/en/changelog. What that page gets right is that a changelog is READ, not scanned like data — so the table is gone. Each release is now a version pill and date in a left rail with the change on the right, whitespace instead of rules, and a sticky version index down the side. Light theme only, by instruction: there is no dark variant and no prefers-color-scheme block.

Full notes

DETAIL NOW COMES FROM THE COMMIT BODY. The table could only ever show a subject; the sheet renders the body too, as paragraphs and bullet lists, with the Session: trailer stripped. The first block shows by default and the rest sits behind a Full notes disclosure, because bodies here run past twenty lines and thirty-seven of them expanded is not a page anyone reads. Write release commits accordingly: the subject is the sentence people read, the first paragraph is the summary they see.

Rendering moved to scripts/_changelog_sheet.py — bash derives, python renders. Markdown support is deliberately just backticks, ** and bare URLs: a changelog needing a full markdown engine is one whose commit messages have stopped being commit messages.

Three things this shook out:

  • _releases.sh gained a sixth field and changelog.sh still read five, so read folded the whole body into session and printed it inside the Session link. Every consumer of a record must read every field.
  • BSD tr does not understand \x1e. Encoding body newlines with it translated the literal characters e, x and 1 instead and shredded every body. It is \036, octal.
  • A <code> chip bound to a 14px token rendered small inside the 16px lede and knocked the line off its baseline. Chips now inherit size and line-height; weight and family are the only type properties they own.
