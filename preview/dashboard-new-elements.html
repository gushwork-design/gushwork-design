Dashboard — new elements

The 21 elements the GTM Command Center needs and exports/dashboard/ does not have, drawn for the library. Prefix gwd-. Every value is an existing --gw-* token — no colour, type step, radius, shadow or spacing value was created. Where the source dashboard used an off-ramp value, the nearest token is used and the swap is recorded in the notice. The shell and the tab bar are excluded: the current build stands.

Token safety, verified not asserted. The element block references 86 distinct --gw-* tokens and every one resolves against foundation/tokens.css. It contains no raw hex, no rgba(), no font-size, radius, shadow or duration literal — grep it. The only lengths written directly are 1px hairlines (per DECISIONS.md → R5) and two letter-spacing values, both reported below as gaps. Two off-ramp measurements were swapped for the nearest step: the 6px meter height → --gw-space-8 and the 6px control radius → --gw-radius-8.

Two values in use still have no token, reported rather than invented, per foundation/new-component-notice.md: 1. Tabular numerals. Every figure in a column needs Inter with font-variant-numeric: tabular-nums, and no --gw-text-* token carries it — the ramp sets card values in the display face. gwd-figure declares it directly. 2. Uppercase tracking. gwd-section-label and gwd-today-tag need letter-spacing on a 10px uppercase run; --gw-text-body-10-sem-tracking is 0, so the value is set in the element.

Worth a decision

The judgement calls, separated from the routine adaptations. Full record in notices/2026-08-11-gtm-dashboard-elements.md.

CallWhat I didThe alternative
The status greens and reds shift Took Badge's green-100 / green-500 and the parallel red steps. The dashboard's emerald and Tailwind red exist in no ramp, so there was no token-safe way to keep them. Add #0d9463 and #dc2626 as ramp steps — a palette change, and it would give the system two greens.
The meter is 8px, not 6 Used --gw-space-8. It reads slightly heavier under a 32px figure but it is a real step. Add a 6px spacing step, which no other component needs.
Emphasis is elevation only The value stays at --gw-text-h5 in both modes; emphasis is shadow-s3 and a hairline. Fixes an emphasis rule that was undefined across the source pages. Bump the value a step. The display ramp jumps 32 → 38, which is a large step for a card that tiles with its siblings.
The pinned column is not darkened Kept table-row's ruling — the first column is distinguished by position and stickiness, not by weight or colour. Darken it as the source dashboard does, and promote the deviation into table-row.
The info-dot is the only tooltip trigger Scoped the trigger to the dot. In the source, the dot marked one card while the tooltip fired from anywhere on it. Keep whole-card hover and drop the dot, which loses the affordance.

Scope. 21 elements, covering every item in the Build column of preview/dashboard-audit-sheet.html except the app header and tab bar — the current shell build stands, so the rail-versus-top-header question is closed and needs no component. The 32 Extend items are not drawn here; they are variants on components that already exist and belong in those components' own specs.

  • Light surface only. Dark treatments follow the per-component Mode convention and are a second pass, not a theme swap — the source dashboard's global .dark class has no equivalent in the library.
  • Not measured. Nothing here exists in Figma yet, so every value is RULED, not measured. Per DECISIONS.md that makes it the least trustworthy kind of spec until someone draws it — five of six rulings checked in the August passes turned out wrong.
  • Controls are live enough to focus and hover; none are wired to state.
  • Not published. To host, add this path to SHEETS in scripts/publish-sheets.sh.
