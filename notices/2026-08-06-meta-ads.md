# Meta Ads dashboard — new elements and deviations

Built 6 Aug 2026. Nine-page app rebuilt on measured Gushwork dashboard components.

Files: `preview/meta-ads-app.html` · `preview/_meta_ads_app.css` ·
`preview/_build_meta_ads_app.py`

---

## Created

### Multi-page shell navigation

The rail acts as a router — clicking a nav row swaps the `section/header` and the Slot
contents. `dashboard-build` covers a single page and the library has no pattern for moving
between pages inside one shell. The live app has nine destinations, so something had to
carry that.

No new visual element: it reuses `list-item` and its measured `selected` state
(`--gw-color-neutral-50`). What is new is the **behaviour**, and the fact that the rail is
now a persistent chrome element rather than page content.

**Where:** `preview/meta-ads-app.html` → the rail, plus `show()` in the inline script.

## Modified

### `dashboard-build` — fixed 1440 × 888 → fluid width, 100vh

A real browser window is not 1440 × 888. The rail keeps its measured 260; the container
flexes. Shell padding becomes `8px 8px 0` so the rail runs flush to the bottom, matching the
measured 880-vs-872 asymmetry.

**Where:** `_meta_ads_app.css` → `.shell`, `.rail`, `.main`

### `kpi-card` — height 198 → `clamp(140px, 21vh, 198px)`, gap 80 → `clamp(12px, 8vh, 80px)`

At 600px tall the KPI row pushed the first table below the fold. **The measured 198 is the
clamp maximum**, so a 1300px+ viewport renders the card exactly as drawn; only short
viewports compress.

**Where:** `_meta_ads_app.css` → `:root --v-kpi`, `--v-kpigap`

### Slot and rail rhythm — clamped, measured value as the ceiling

| Value | Range | Measured |
|---|---|---|
| slot padding + section gap | 16 → 40 | 40 |
| header top padding | 16 → 40 | 40 |
| rail padding | 12 → 24 | 24 |
| rail title→nav gap | 14 → 40 | 40 |
| nav group gap | 8 → 24 | 24 |

**Where:** `_meta_ads_app.css` → `:root`

### `section/card-layout` — wide-screen breakpoints the component does not define

- **≥ 1800** — analytics grid 3 → 6 columns at `KPI cards=1`; 2×3 → 3 at `=2`
- **≥ 2200** — `=2` also → 6 columns; slot padding-inline → `clamp(40px, 4vw, 96px)`
- **KPI area capped** — 480 at `=1`, 820 at `=2`

**Where:** `_meta_ads_app.css` → `@media (min-width:1800px)`, `(min-width:2200px)`

### Rail — only the nav list scrolls

Nine nav items plus the user-card need ~683px, so below roughly 700px tall the whole rail
was scrolling, user-card included. The rail is now `overflow: hidden` with only
`.rail__container` scrolling, so the user-card stays pinned.

**Where:** `_meta_ads_app.css` → `.rail`, `.rail__container`

### `Graph Type=Bar` — same values, rebuilt as a per-row grid

Labels and bars in two separate columns drift ~2px per row — measured at **14px** on the
first row — because a 12px label and a 10px bar share one gap. Each label now shares a grid
row with its bar. No measured value changed; only the layout mechanism.

**Where:** `_build_meta_ads_app.py` → `graph_bar()`

### Table columns — first column unsized

With every column explicitly sized, the browser spread leftover space across all of them: a
16px action column measured **84px** at 1600, and data columns drifted past their measured
widths (Spend 120 → 157). The first column now absorbs the slack; data columns hold their
measured widths exactly; the action column is pinned at 64.

**Where:** `_build_meta_ads_app.py` → `table()`, `_meta_ads_app.css` → `.dt__act`

### Scrollbars hidden on the Slot and rail

`scrollbar-width: none` plus a zero-size `::-webkit-scrollbar`. **A product choice, not a
measured value** — Figma has no scrollbar spec. Costs a scroll affordance: there is no cue
that content continues below the fold, which bites hardest on the denser pages.

**Where:** `_meta_ads_app.css` → `.slot`, `.rail`, `.rail__container`

## Worth a decision

**1. The `card-layout` KPI cap.** This is the only place I overrode a measured value because
it produces a bad result at scale, rather than adapting one. The measured `KPI cards=1` split
is 400/676 — 36.9% — which on a 2400px display leaves a single kpi-card **715px wide** around
a 32px number. I capped it at 480. Either that cap belongs in the component spec, or the
split should be absolute rather than proportional. **Your call.**

**2. Should the vertical clamps become part of the component spec?** Seven measured values
are now clamped with the Figma figure as the maximum. That pattern held up across nine pages
and three viewport heights. If it is right, it belongs in Figma as a min/max rather than
living in one project's CSS.

**3. Hidden scrollbars.** Defensible for a dense dashboard, but it removes an affordance.
Worth a yes or no so it stops being re-decided per project.

## Tokens

Everything above uses existing tokens. **No new colour, type, radius, shadow or spacing value
was introduced.**

Three values in use have **no token** and are flagged rather than invented:

| Value | Where | Note |
|---|---|---|
| display face at 18/500 | rail title, With Dropdown cells | heading ramp starts at 22 |
| display face at 20/500 | analytics-card value | measured on the component |
| Inter Medium 10 at line-height 1.6 | kpi-card title | `body-10-med` is 10/15 |

Those three are measured off Figma components — they are gaps in the **token set**, not
inventions here.
